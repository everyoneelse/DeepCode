# 🚀 快速开始指南

欢迎使用Cursor Agentic Coding Prompts！这个指南将帮助您在5分钟内开始使用我们的prompt集合，将复杂的编程需求转换为高质量的代码实现。

## 📋 准备工作

### 1. 环境要求
- ✅ Cursor编辑器（最新版本）
- ✅ 基本的编程知识
- ✅ 明确的项目需求或论文资料

### 2. 获取Prompts
1. 下载或克隆这个仓库
2. 在Cursor中打开 `cursor_prompts` 目录
3. 根据需要选择合适的prompt文件

## 🎯 选择您的使用场景

### 场景A：论文转代码 📚➡️💻
**适用于**：学术论文实现、算法复现、研究项目

**快速流程**：
```
1. 📊 论文分析 → 2. 🏗️ 代码规划 → 3. ⚙️ 项目设置 → 4. 💻 代码实现
```

**开始步骤**：
1. 打开 `core_prompts/paper_analysis.md`
2. 复制prompt内容到Cursor
3. 提供论文内容（PDF文本、链接或直接粘贴）
4. 按照输出结果继续下一步

### 场景B：需求转代码 💡➡️🔧
**适用于**：Web应用、API开发、工具开发、业务系统

**快速流程**：
```
1. 🏗️ 代码规划 → 2. ⚙️ 项目设置 → 3. 💻 代码实现
```

**开始步骤**：
1. 打开 `core_prompts/code_planning.md`
2. 复制prompt内容到Cursor
3. 详细描述您的项目需求
4. 按照生成的计划继续实现

## 🔥 5分钟快速体验

### 示例：创建一个简单的任务管理API

**步骤1：代码规划（2分钟）**
```
[复制 core_prompts/code_planning.md 的内容]

我需要开发一个简单的任务管理API，包含：
- 用户注册和登录
- 创建、查看、更新、删除任务
- 任务状态管理（待办、进行中、已完成）
- 使用Python + FastAPI + SQLite
- 包含基本的API文档

请生成详细的实现计划。
```

**步骤2：项目设置（1分钟）**
```
[复制 core_prompts/project_setup.md 的内容]

项目信息：
- 项目名称: simple-task-api
- 项目类型: web_app
- 技术栈: Python, FastAPI, SQLite
- 特殊需求: API文档, 简单认证
```

**步骤3：代码实现（2分钟）**
```
[复制 core_prompts/code_implementation.md 的内容]

请根据之前的实现计划，首先实现：
1. 基本的FastAPI应用结构
2. 用户模型和任务模型
3. 用户注册和登录API
4. 基本的任务CRUD API

请逐个文件实现，包含完整的代码和注释。
```

## 📚 核心Prompt使用指南

### 1. 论文分析 (`paper_analysis.md`)
**何时使用**：当您有学术论文需要转换为代码时

**输入格式**：
- 论文PDF的文本内容
- 论文链接
- 论文的关键章节文本

**输出结果**：
- 结构化的YAML格式分析
- 包含算法、架构、实验设置等所有技术细节

### 2. 代码规划 (`code_planning.md`)
**何时使用**：需要将需求或论文分析转换为实现计划时

**输入格式**：
- 论文分析结果（YAML格式）
- 直接的文本需求描述
- 项目规格说明

**输出结果**：
- 完整的项目架构设计
- 详细的文件结构规划
- 分阶段的实现计划

### 3. 代码实现 (`code_implementation.md`)
**何时使用**：根据实现计划生成具体代码时

**输入格式**：
- 完整的实现计划
- 特定文件的实现需求
- 功能描述和技术要求

**输出结果**：
- 完整的、可运行的代码文件
- 包含文档字符串和注释
- 适当的错误处理和测试

### 4. 项目设置 (`project_setup.md`)
**何时使用**：需要快速创建项目结构和配置时

**输入格式**：
- 项目基本信息
- 技术栈选择
- 特殊需求说明

**输出结果**：
- 完整的目录结构
- 所有配置文件内容
- 开发环境设置脚本

## 💡 使用技巧

### 1. 渐进式开发
- 不要试图一次实现所有功能
- 先实现核心功能，再添加扩展特性
- 每个阶段都要测试验证

### 2. 清晰的输入
- 提供尽可能详细的需求描述
- 明确技术栈和约束条件
- 给出具体的示例和期望

### 3. 迭代改进
- 基于输出结果提供反馈
- 逐步完善和优化代码
- 根据需要调整实现方案

### 4. 结合使用
- 多个prompt可以组合使用
- 前一个prompt的输出可以作为下一个的输入
- 保持工作流的连贯性

## 🔧 常见问题解决

### Q: 输出的代码不完整怎么办？
**A**: 
- 尝试分解需求，逐个实现
- 提供更具体的文件级别需求
- 使用"继续实现"的提示

### Q: 生成的架构不符合需求怎么办？
**A**:
- 在规划阶段提供更详细的约束条件
- 明确指出不合适的部分并要求调整
- 提供参考架构或类似项目的例子

### Q: 如何确保代码质量？
**A**:
- 要求包含单元测试
- 明确代码规范要求
- 要求添加详细的文档和注释
